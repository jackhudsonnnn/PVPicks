# Table rules

- Table screen is a poker-style felt: seating/rail/seat-chip rules live in `src/features/table/seating.ts` (tested); components under `src/features/table/components` only render them. Seat DOM order follows table order; positions snap while arrivals fade, with no retained exiting seats. Why: keeps crowding testable and prevents interrupted travel or outgoing avatars overlapping current seats.
- Host permissions (incl. who can start bets and per-member limits on betting, texts, reactions, GIFs) live in `src/features/table/hosts.ts` (tested); the store reducer enforces them for every author, including sample data, and `host-panel.tsx`/`member-settings-dialog.tsx` only render. Chat reactions toggle via `src/features/table/reactions.ts` (tested); the GIF catalog is `src/features/table/gifs.ts` so a live GIF search can replace it. Why: rules stay testable and UI stays swappable.
- Settlement payment tracking (sent/confirm/dispute, forgive and ask-to-forgive, outstanding list, `netSettleUps` = the app-wide points number) lives in `src/features/table/settlements.ts` (tested); status and forgive asks are stored on the settlement message, and shared `PaymentActions` renders buttons only in personal settle-up views. Chat `SettlementCard` renders original lines without reading payment status or requests and links to Friends. Why: public summaries stay fixed while payment tracking stays between the payer and recipient.
- Friends person nets are derived in `social/settle-groups.ts`; the receipt popup uses individual payment commands, with dated rows and Sent/Received columns. Legacy grouped commands retain revision validation. Why: receipt confirmation cannot clear unrelated opposite-direction debts.
- `social/settle-changes.ts` reconciles net changes after message-changing store actions; each party reviews their own warning before sending or asking forgiveness, and grouped actions validate ledger revisions. Prototype reviews stay in memory; the gated backend stores them durably. Why: pending claims and stale dialogs cannot clear new debt.
- Peers "true/settle" balances are computed in `src/features/table/scenarios.ts` (tested; screens use the memoized `cachedPeerScenarios`) from stored `deltas` and pending pots; never store them (a server would store the true balance). Settling zeroes settle balances. Chat unread rules live in `src/features/table/unread.ts` (tested), with last-read ids kept locally. Why: one stored value, derived views.
- The profile popup shows one person's bets at this table and nothing else; settle-up cards deep-link to it with `/tables/$tableId?profile=<id>`. Why: one profile view per person, no per-pair history page.
- Quick Picks (share code, one-way subscribe, exact copies, copies follow the source's result, host override = wash) rules live in `src/features/table/quick-picks.ts` (tested); the store's `propose`/`settle`/`overrideQuickPick` reducers fan out and enforce them. Copies use id `<sourceBetId>@<tableId>` and are never re-shared. Why: one place for cross-table rules; points never cross tables.
- Chat window bounds live in `chat-window.ts` (tested), with scroll anchoring in `use-chat-window.ts`; unread calculations use the full ordered source, never the rendered slice. Windowed history rows are not wrapped in AnimatePresence, so pruning removes DOM immediately. Why: mobile and desktop can jump across large unread gaps without retaining thousands of rows or losing their read position.
